# Engineering write-ups

Gavelhouse was a compliance-first HOA/condo management SaaS, built solo,
shipped to production on Cloudflare, and wound down in June 2026. These
documents walk through specific pieces of the system in detail, with code
excerpts pulled from the source and notes on where each design still has
real limits. Every claim traces to a file in this tree, and every number
traces to the command that produced it: most of them to
[`pnpm run metrics:generate`](../scripts/collect-metrics.ts) or to a dated
document under [`../docs/`](../docs/).

They are retrospective. The plans, runbooks, audit runs, and QA records that
were written *during* the build stayed in [`../docs/`](../docs/) rather than
being rewritten for an audience.

## If you read one thing

[`ACCOUNTING-ENGINE.md`](./ACCOUNTING-ENGINE.md) covers the per-fund balance
invariant the whole product was built around: the chart of accounts and
report layer built on top of it, and the one place those reports fall short
of it, addressed by file and line rather than left for a reader to find.

[`../docs/`](../docs/) holds the day-to-day working record instead: the
pre-launch recon passes, the per-workspace defect inventories, the go-live
checklist, the production incident bug reports, the badge and
directory-listing campaigns, and the runbooks for infrastructure that no
longer exists, all dated and kept as written.
[`../docs/screenshots/`](../docs/screenshots/) holds the full, working
capture archive; [`./screenshots/`](./screenshots/) holds the six images
this repository shows a reader here.
